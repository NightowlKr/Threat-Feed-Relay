# 수집·보강 설계

연결: FR-001~FR-003, FR-008~FR-010, FR-018.
외부 자료는 신뢰하지 않는 데이터로 취급하며 코드·명령으로 실행하지 않습니다.
작업 상태·멱등성·입력 manifest는 [아키텍처](architecture.md), 외부 통신 제한은 [보안·운영](security-operations.md)을 따릅니다.

## 단계와 산출물

| 단계 | 입력 | 산출물·완료 조건 |
| --- | --- | --- |
| 수집 | 활성 소스 설정 | 실행 기록과 제한된 크기의 원본 응답 |
| 파싱 | 응답·파서 버전 | 타입이 지정된 후보 지표와 거부 사유 |
| 정규화 | 후보 지표 | 정규화 버전이 붙은 IP/CIDR/Domain/URL |
| 스냅샷 검증 | 정규화 지표·수집 상태 | 완전성 검증을 통과한 소스 스냅샷 |
| 통합·보강 | 유효 스냅샷 | 출처 관계와 시각이 있는 DNS·ASN 등의 메타데이터 |
| Profile 평가 | 고정 입력 manifest | 조건 평가·집계 후 모든 필수 배포 제외를 적용한 지표 |
| 산출물 생성 | 선택 지표·출력 계약 | 정렬·중복 제거·체크섬 검증을 마친 임시 파일 |
| 게시 | 검증 산출물 | 현재 버전 포인터의 원자적 전환과 게시 기록 |

Python 내부 CLI 작업자를 기준선으로 하며 전달·쓰기 책임은 [아키텍처](architecture.md)를 따른다.
원본 관측을 저장한 다음 모니터링·수집 예외를 평가하고 정제 membership을 계산한다.

## 소스 어댑터 계약

- 각 어댑터는 소스 ID, 응답 형식, 지원 지표 타입, 파서 버전을 갖는다.
- 전체 스냅샷과 증분 갱신 방식을 명시하여 누락·삭제의 의미를 구분한다.
- 연결·읽기 시간 제한, 최대 응답 크기, 재시도 횟수는 설정 항목으로 둔다.
- 소스별 주기·호출 제한·인증·이용 조건은 초기 소스 선정 D-01에서 확인한다.
- HTTP 상태와 실패 원인을 저장하고 인증값·민감한 쿼리 문자열은 로그에서 가린다.
- 실패 재시도는 지연을 두며 반복 실패가 다른 소스 처리를 막지 않게 한다.
- 빈 응답·급격한 건수 변동의 승인 조건과 임계값은 D-01, D-07에서 정한다.

## 정규화 제안

| 타입 | 초기 제안 | 결정해야 할 경계 |
| --- | --- | --- |
| IP | 검증된 IP 파서의 표준 표현 사용 | IPv4-mapped IPv6, 특수 용도 주소 처리 |
| CIDR | 주소 계열·prefix 검증, 네트워크 주소 사용 | host bit가 있는 입력의 거부 또는 보정 |
| Domain | 소문자·IDNA 정규형 후보 | 후행 점, 국제화 도메인, wildcard 허용 여부 |
| URL | URL 파서로 구조 검증, scheme·host 처리 | 허용 scheme, 포트, 경로·쿼리·fragment 보존 규칙 |

규칙은 D-02에서 확정하고 parser·normalizer 버전을 입력 manifest에 남긴다.
서로 의미가 달라질 수 있는 경로·쿼리의 대소문자와 순서를 임의로 바꾸지 않는다.
URL의 자격증명 구간, 제어문자, 개행, 파싱 불일치는 거부 또는 격리하는 방안을 적용한다.
URL 지표는 수집 대상 주소가 아니다. 지표에 적힌 URL을 열거나 실행하지 않는다.
실제 소스 endpoint 접근은 승인된 설정을 사용하고 redirect 목적지도 접근 정책에 따라 검증한다.

## 생성·게시와 장애 복구

1. [입력 manifest 계약](architecture.md)에 따라 소스·모든 정책·예외·보강·라우팅·기준 시각을 고정한다.
2. [Profile 평가 계약](profiles-api.md)에 따라 후보 선택·집계·최종 배포 제외를 수행한다.
3. 타입별 고정 정렬과 중복 제거 후 공개 위치와 분리된 임시 산출물을 만든다.
4. 형식, 건수, 체크섬을 검증하고 성공한 산출물만 게시 대상으로 표시한다.
5. 현재 게시가 허용된 정책·입력 세대와 예상 공개 revision을 조건부 검사한 뒤 포인터를 전환한다.
   구세대 작업이나 동시 게시 충돌은 자동 덮어쓰기하지 않고 보관·재평가한다. 실패 시 기존 포인터를 유지한다.
6. 중단 후에는 실행 ID·체크섬·게시 상태로 재개하거나 동일 입력을 재생성한다.

다중 파일 다운로드·불변 revision·형식·캐시는 [Profile·API](profiles-api.md)의 출력 계약을 따른다.
취소는 안전한 checkpoint에서 반영하고 미완성 segment는 게시하지 않는다.
소스별 최근 성공·거부/중복/만료·지연과 생성·게시 상태를 구분한다.

## 파서 설정과 미리보기

지원 범위는 plain_line, token_position, regex, CSV/TSV, hosts, JSON/JSONL이며 XML/STIX/custom_plugin은 후속 확장이다.
입력 예에는 `deny from` 뒤 토큰, CSV 첫 열, IPv4/IPv6 혼합, hosts 주소·이름, JSON URL/IP가 포함된다.
구분자·헤더·열 번호·주석·encoding·regex·JSONPath/JMESPath는 파서별 설정으로 검증한다.
실행 코드나 shell 명령을 설정 값으로 받지 않는다.

미리보기는 제한된 샘플로 추출·정규화·유효/거부/중복 건수와 사유를 보여준다.
검증한 새 파서 버전을 활성화하고 기존 실행 버전을 바꾸지 않는다.
정규식 CPU·시간, XML 외부 엔터티, JSON 깊이·크기, plugin 권한·격리 한도를 둔다.
형식 불일치나 전량 파싱 실패를 정상 빈 스냅샷으로 승인하지 않는다.

## DNS·ASN 보강

### 지표 기원

`direct_feed`, `derived_domain`, `derived_url_host`, `derived_dns`, `manual`, `derived_asn`을 구분한다.
파생 지표는 부모 지표·출처·정책·보강 버전을 연결한다.
DNS 응답 IP를 직접 수집 악성 IP와 같은 신뢰 점수로 자동 취급하지 않는다.
ASN 대역을 조회했다는 이유만으로 대역 전체를 차단 대상으로 확대하지 않는다.

### Resolver 관리와 조회

시스템 Resolver와 사용자 지정 UDP/TCP Resolver를 초기 범위로 두고 DoT/DoH는 확장 단계로 둔다.
설정에는 이름·주소·프로토콜·우선순위·timeout·재시도·동시성·TCP fallback·EDNS 정책을 둔다.
허용 Resolver의 목적지와 포트를 제한하며 일반 Source SSRF 예외와 분리한다.
상태는 unknown/healthy/degraded/unreachable/disabled로 구분한다.

- A, AAAA, CNAME과 전체 응답 값·TTL·조회 시각·지연·Resolver를 저장한다.
- NOERROR, NXDOMAIN, SERVFAIL, REFUSED, FORMERR, NOTIMP, TIMEOUT, NETWORK_ERROR, INVALID_RESPONSE를 구분한다.
- 응답 비교의 union과 consensus 정책을 구분하고 필요한 Resolver 수를 설정한다.
- 응답 불일치는 관측 사실로 표시한다. 모든 조회 실패를 정상 빈 집합이나 안전한 도메인으로 취급하지 않는다.
- CNAME 루프·깊이·응답 크기를 제한하고 CDN/공유 IP 확대로 인한 오차단을 방지한다.
- URL은 host만 분리하여 DNS 대상으로 사용할 수 있고 URL 자체에 접속하지 않는다.
- Resolver 정책은 Profile 또는 DNS watch 정책에 연결하며 Source마다 강제로 복제하지 않는다.

### DNS 변화 이력

도메인-IP 관계의 first_seen/last_seen, 활성 구간, 관측·Resolver 수, 이전·현재 응답을 저장한다.
added/removed/unchanged/reactivated 및 CNAME 변경·NXDOMAIN·충돌 사건을 구분한다.
한 번의 timeout이나 일시적 NXDOMAIN으로 기존 파생 지표를 즉시 삭제하지 않는다.
제거 유예·연속 관측 기준·stale 사용은 D-03/D-04에 기록하고 TTL과 threat 수명을 분리한다.
직접 지표, DNS 파생 지표, 혼합 출력은 Profile에서 명시적으로 선택한다.

### ASN/CIDR 데이터

저장 범위는 IP 대역, ASN, AS type, owner, country 및 제공자·시각·데이터셋 버전이다.
GIS·지도·정밀 위치 추적은 제외한다.
로컬 데이터셋의 longest-prefix match(LPM)를 우선하고 정책에 따라 외부 조회로 보완한다.
IPv4/IPv6를 분리하며 ASN/소유자/국가 정보는 악성 여부 판단과 구분한다.

- 개별·일괄·예약 조회, 진행률·취소·재개·실패 항목 재시도를 제공한다.
- batch 크기·동시성·호출량·재시도 backoff는 제공자 제한에 맞춰 설정한다.
- 데이터셋은 버전·checksum·건수·수입 상태·이용 조건을 관리하고 검증 후 활성화한다.
- 상태는 pending/matched/not_found/expired/failed/rate_limited/disabled를 구분한다.
- 오래된 결과와 조회 실패를 구분하고 공급자 장애가 원본 관측을 제거하지 않게 한다.
- 개별 결과와 일괄 데이터셋의 충돌·우선순위는 제공자 정책으로 기록한다.

### 수용 검증

동일 도메인의 여러 A/AAAA, CNAME 변화·순환, Resolver 불일치와 전체 실패,
TTL 경계·일시적 제거·재등장을 합성 데이터로 시험한다.
ASN은 중첩 prefix LPM, IPv6, not_found, 데이터셋 교체 실패, rate limit, 배치 재개를 시험한다.
선택한 보강 ID·버전을 출력 입력 manifest에 고정하여 재현성을 확인한다.

## 제공자 연동

아래는 연동 요청 범위입니다. 최신 endpoint·인증·호출량·재배포 권리는 구현 시 공식 자료로 D-01/D-09에 기록합니다.

| 대상 | 대화에서 확인한 목적 | 구분할 계약 |
| --- | --- | --- |
| 공공데이터 WHOIS IP, 데이터셋 15094277 | IP의 WHOIS 정보 보강 | 요청 주소 계열, 응답 필드·없음·오류, 인증·호출 제한 |
| 공공데이터 분기 IoC, 데이터셋 15128323 | 기간별 IoC 수집 | 분기 식별·발행/수정 시각, 전체본/증분본·정정 처리 |
| C-TAS | 인증된 차단/해제 자료 다운로드 | block_ip/block_domain/release_ip/release_domain, day/month/year, level 1/2, CSV/JSON/ZIP |
| 일반 외부 Feed | URL·파일의 위협 지표 수집 | TXT/CSV/hosts/JSON 등 파서, 전체/증분, 신뢰·이용 조건 |
| ASN 제공자·로컬 데이터셋 | IP 대역·ASN/type/owner/country | LPM 데이터셋과 개별 API의 버전·갱신·이용 조건 |

C-TAS는 대화에서 2020년 이후 기간 조회가 요청됐다. 실제 제공 시작일과 보존 범위는 확인해야 한다.
실제 인증정보는 비밀 참조로 관리한다. 로그인·요청 예시가 자동 수집 허가나 현재 API 계약을 의미하지 않는다.

### 어댑터별 필수 설정

제공자 ID, 공식 문서 참조, 승인한 endpoint, 인증 비밀 참조,
TLS/redirect 정책, 파서·정규화 버전, 갱신 주기·호출량,
전체/증분 의미, 시간대·기간 경계, 완전성 판정, 보존·재배포 조건을 기록한다.
인증 세션이 필요한 경우 승인된 로그인·갱신 흐름만 사용하고 오류 시 인증 우회를 시도하지 않는다.

### 차단·해제와 기간 자료

- 해제 이벤트는 해당 제공자의 활성 관계에만 적용한다. 다른 출처의 악성 관측까지 삭제하지 않는다.
- 차단·해제의 유효 시각과 수집 시각을 분리하고, 역순 도착·중복 다운로드를 멱등 처리한다.
- 일·월·연 자료가 겹치면 제공자 이벤트 ID 또는 검증된 복합 키로 중복을 제거한다.
- 해제 자료가 없는 날은 “해제 없음”일 수 있다. 인증 오류·파일 누락·정상 빈 결과와 구분한다.
- 기간 전체가 검증되기 전에는 완료로 표시하거나 기존 자료를 전량 교체하지 않는다.
- 과거 backfill과 실시간 갱신은 checkpoint를 분리하고 현재 상태가 오래된 이벤트로 되돌아가지 않게 한다.

### 파일·파서 안전

ZIP의 경로 탈출·압축 폭탄·파일 수/해제 크기·중첩 깊이를 제한한다.
로그인 HTML·오류 JSON을 정상 Feed로 파싱하지 않는다.
CSV/JSON의 필드·encoding·헤더 변경은 schema 오류로 보고하고 원문 참조를 보존한다.
공공 WHOIS 응답을 악성 Feed나 정확한 ASN 데이터로 무조건 대체하지 않는다.

테스트는 합성 또는 승인된 자료만 사용한다.
Provider 정상·인증 만료·rate limit·정상 빈 해제·중복 기간·순서 역전·손상 ZIP을 검증한다.
라이선스 미정 소스는 외부 재배포를 활성화하지 않는다. 프로젝트 라이선스도 별도 결정 전 추가하지 않는다.
