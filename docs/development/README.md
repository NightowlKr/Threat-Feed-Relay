# 개발 문서 안내

이 폴더는 구현·검토·유지보수를 위한 개발 자료입니다.
최종 사용자 매뉴얼이나 실행 가능한 배포 패키지가 아닙니다.

## 읽는 순서와 책임

| 문서 | 단일 책임 |
| --- | --- |
| [요구사항](requirements.md) | 제품 목표·범위, FR-001\~FR-021·NFR-001\~NFR-007과 수용기준 |
| [아키텍처·데이터](architecture.md) | 기술 후보, 작업 계약, 데이터 모델, DB HA·샤딩 |
| [수집·보강](pipeline.md) | 파서·DNS·ASN·제공자 연동과 관측 수명 |
| [Profile·배포 API](profiles-api.md) | 예외·Allowlist·집계·출력과 관리 API |
| [보안·운영](security-operations.md) | 인증·권한·네트워크, 설치·로그·백업·업데이트 |
| [개발 절차·결정](workflow.md) | 단계 계획, D-01\~D-12, Git 운영, 구현 작업 양식 |
| [검증](verification.md) | 문서 점검 및 미실행 기능 수용 검증 |

기능 범위는 요구사항, 실제 정책·필드는 담당 설계 문서, 남은 선택은 결정 로그를 기준으로 합니다.
같은 계약을 여러 문서에 재정의하지 않고 담당 문서를 연결합니다.

## 상태와 근거

| 상태 | 해석 |
| --- | --- |
| 사용자 요청 | 직접 요청된 기능·제약; 세부 구현 전부의 승인을 뜻하지 않음 |
| 대화 기준선 | 전달된 설계 방향; 실제 호환성 검증 전 |
| 설계 제안 | API·필드·처리 정책·수용기준의 구체화 |
| 미정 | 구현 전 선택·실측·이용 조건 확인 필요 |
| 검증 완료 | 실제 실행한 점검에 한정 |

별도 확정 기록이 없는 API 경로·필드·수용기준은 설계 제안입니다.
기술 버전은 현재 지원·호환성의 보증이 아니며 구현 시 공식 자료와 실행 결과로 확인합니다.
이미 요청된 기능을 다시 미정으로 돌리지 않고 남은 상세 선택만 결정 로그에 기록합니다.
코드 구현·외부 제공자 호출·성능·보안·복구 시험은 아직 수행하지 않았습니다.

## 문서 유지 기준

새 파일을 추가하기 전에 기존 담당 문서의 절로 포함할 수 있는지 확인합니다.
요구사항·결정 ID를 변경하거나 폐기할 때 이유와 관련 설계·검증의 영향을 함께 기록합니다.
중복된 정책은 한 곳으로 합치되 보안 불변조건과 고유 수용기준을 삭제하지 않습니다.
개인 대화 URL·원문·인증값은 포함하지 않습니다.
이 폴더는 개발 자료라는 용도 구분일 뿐, 공개 저장소에서 비공개가 되는 위치는 아닙니다.
